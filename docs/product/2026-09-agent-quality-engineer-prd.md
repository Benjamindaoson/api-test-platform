# PRD：Agent Quality Engineer v0.1 — RAG Release Gate

## 概览

**状态：** Draft

**目标：** 为企业内部 RAG + 只读工具调用 Agent 提供无人值守的变更测试与发布结论。

**问题：** Prompt、模型、检索索引、知识库和工具定义变更会造成传统代码测试难以发现的质量退化。团队缺少一个从变更到可复验证据的自动闭环。

## 目标与成功指标

### 目标

1. 一次 Agent 变更可自动触发并完成质量评估。
2. 结论可追溯到版本、测试数据、评估器和完整执行轨迹。
3. 系统能按策略输出 `pass`、`block` 或 `escalate`，而不是仅输出分数。

### 成功指标

v0.1 不预设虚构基线。设计伙伴接入后建立：

- 已知高严重度历史回归发现率；
- 误报率；
- 变更到结论的 P50/P95 时长；
- 单次评估成本；
- 需要人工升级的运行比例。

## 目标用户

| 角色 | 需要完成的任务 |
| --- | --- |
| AI 工程师 | 为 Agent 建立评估集、查看失败归因、修复后复验 |
| 质量工程师 | 定义质量策略、审查评估器和覆盖缺口 |
| 发布负责人 | 根据证据决定是否允许合并或发布 |
| 编码 Agent | 接收包含复现任务、预期/实际和证据的修复任务 |

## 范围

### In

- 单个 RAG 或 RAG + 只读工具调用 Agent；
- 版本化评估集和评估器；
- 变更快照：代码、Prompt、模型、检索配置、知识库版本、工具 schema；
- 正确性、Grounding、拒答、引用、Prompt injection、工具轨迹、延迟与成本检查；
- 沙箱或模拟器中的自动运行；
- 证据包、版本比较和策略结论；
- 失败聚类及面向编码 Agent 的修复任务草稿。

### Out

- 自动合并或推送修复代码；
- 有写入、副作用或资金/生产操作的工具自动执行；
- 多 Agent 自由协作；
- 通用 BI 或测试管理；
- 对生产用户数据无边界地抓取与保存。

## 用户故事与验收标准

### US-1：注册可评估的 Agent

作为 AI 工程师，我要登记 Agent 的版本、入口、知识库版本和允许工具，以便测试结论可以被复现。

- Given 一个 Agent 已登记，When 创建评估运行，Then 证据包必须记录代码、Prompt、模型、索引和工具 schema 的不可变版本标识。
- Given 缺少任一必需版本标识，When 请求运行，Then 系统不得输出 `pass`，并返回 `escalate` 与缺失项。

### US-2：无人值守运行评估集

作为发布负责人，我要在变更后自动运行已批准的评估集，以便无需人工逐条操作测试。

- Given 已配置变更触发和评估策略，When 检测到目标变更，Then 系统自动创建运行并记录触发来源。
- Given 运行中的某项依赖不可用，When 超过策略超时，Then 运行标记为 `escalate`，并保存已完成检查的证据。

### US-3：评估 RAG 答案质量

作为质量工程师，我要同时检查答案正确性、Grounding、引用和拒答，以便“回答流畅但没有依据”的版本不能放行。

- Given 有参考答案或确定性规则的案例，When 输出不满足规则，Then 对应案例必须失败并保存输入、上下文、输出和评估理由。
- Given 缺少足够检索依据的案例，When Agent 给出确定性事实答案，Then 拒答/不确定性策略检查必须失败。
- Given 有检索上下文，When Agent 引用不存在或不支持结论的来源，Then Grounding 检查必须失败或升级。

### US-4：测试对抗和异常条件

作为质量工程师，我要让系统自动覆盖恶意、边界和依赖异常条件，以便不只验证正常问答。

- Given 启用 Prompt injection 测试集，When 输入要求忽略系统规则或泄露受保护内容，Then Agent 不得执行越权工具调用或返回受保护数据。
- Given 模拟检索为空或工具超时，When Agent 执行任务，Then 结果必须符合定义的拒答或降级策略，而非编造成功答案。

### US-5：得到发布结论和证据

作为发布负责人，我要获得一个可解释的 `pass`、`block` 或 `escalate` 结论，以便做发布决策。

- Given 所有阻断级策略通过，When 运行结束，Then 系统输出 `pass` 和完整证据包链接。
- Given 任一阻断级策略失败，When 运行结束，Then 系统输出 `block`，列出失败案例、失败维度和复现上下文。
- Given 证据不完整、评估器冲突或依赖受阻，When 运行结束，Then 系统输出 `escalate`，不得降级为 `pass`。

## AI 行为与评估契约

| 行为 | 评估方法 | 放行规则 |
| --- | --- | --- |
| 检索相关性 | 参考文档、确定性标签或校准 Judge | 低于策略阈值则 block/escalate |
| 回答正确性 | 参考答案、规则和版本化 Judge rubric | 必须保留理由与模型版本 |
| Grounding/引用 | 引用解析 + 上下文支持度评估 | 无依据事实不可 pass |
| 拒答 | 无答案/冲突答案测试集 | 必须符合指定拒答策略 |
| 工具选择与参数 | 工具模拟器和 schema 断言 | 越权或错误调用 block |
| 安全 | 注入、数据泄露、权限边界测试集 | 高严重度命中直接 block |

LLM Judge 只能作为可校准评估器，不能成为唯一事实来源。每个 Judge 必须记录模型、Prompt、rubric、输入和输出；确定性检查优先。

## 证据包

每次运行必须生成：

- 变更与配置快照；
- 评估集和案例版本；
- 每一步检索、模型和工具 Trace；
- 评估分数、规则、Judge 理由；
- 聚类后的失败、复现输入和预期/实际；
- 最终结论、触发策略与时间成本。

## 全局边界与恢复策略

| 场景 | 期望处理 |
| --- | --- |
| 评估器不可用 | `escalate`；保留部分证据；不允许 pass |
| Judge 结论冲突 | `escalate` 或按明确策略加入确定性复核 |
| 检索为空 | 验证拒答/降级，不将其当作正常成功 |
| 工具超时/错误 | 在模拟器中执行恢复策略，记录完整轨迹 |
| 脱敏失败 | 停止 Trace 落库并生成安全事件 |
| 同一版本结果不稳定 | 标记为 flaky；不得以单次成功 pass |

## 度量与隐私

必须记录 `evaluation_run_created`、`case_executed`、`evaluator_completed`、`policy_verdict_issued`、`failure_clustered`、`repair_task_generated` 等事件。

Trace 采集需明确：捕获的数据类型、离开进程前的脱敏、存储前的二次脱敏、访问审计、保留期限、删除链路和失败样本的定向采样。默认不保存不必要的原始用户数据。

## 依赖、风险和停止条件

- 需要一个设计伙伴提供脱敏评估集和历史失败案例。
- 需要可隔离的 Agent 与工具模拟环境。
- 若无法建立可校准的 Grounding/正确性评估器，v0.1 仅可作为观察工具，不可做自动发布门禁。
- 若无法证明测试效果优于现有回归，停止扩展范围，先修正 Benchmark 与评估数据。

## 里程碑

1. **Benchmark 可运行：** 历史案例、变异案例、基线流程。
2. **RAG Release Gate：** 自动运行、核心评估、证据包和策略结论。
3. **设计伙伴试点：** 接入一个内部 Agent，采集真实结果。
4. **工具调用扩展决策：** 仅在 v0.1 指标证明有效后进入下一阶段。
